## Confirmed defects

### 1. MEDIUM — Ordinary words in the user's own writing are treated as raw Schwartz labels, and the failure kills the whole review batch

**Location:** `src/north_star/review.py:55-60` (pattern), `src/north_star/review.py:309-312` (check); consumed via `src/north_star/assessment.py:293` → `src/north_star/runtime.py:620-650`.

**Trigger:** any accepted quotation containing a standalone `security`, `power`, `tradition`, `achievement`, `conformity`, `stimulation`, `hedonism`, `benevolence`, `universalism`, or `self direction`.

**Observed:**
```
$ python -c "from src.north_star.review import _INTERNAL_LABEL_PATTERN as P; ..."
True  security     | I set up an emergency fund for security.
True  tradition    | We kept the family tradition of Sunday lunch.
True  achievement  | Signing off on that was a real achievement for me.
True  power        | I made sure the power was switched off before leaving.
```
`validate_review` accumulates `internal_value_label_in_quote:<id>` into `errors` and raises for the **entire batch** (`review.py:311-313`), so every other entry's decision — including a perfectly valid alternative quotation — is discarded. In `OpenAINorthStarRuntime.__call__` this lands in the `except ReviewValidationError` branch, calls `provider.invalidate`, and retries; if the second attempt also quotes the word, the week ends as `status="failed"`, `reason="provider_invalid"`, the card is suppressed, the user sees "A North Star Moment could not be prepared", and both paid attempts are consumed on a deterministic-input failure.

**Expected** per the authoritative spec, `docs/north_star/north_star_moment.md:442`: *"Internal value labels | No raw internal Schwartz label appears in card fields. Omit an unsuitable quotation rather than rewriting it."* — omit that one candidate, keep the batch. §3 also states the rule "does not … permit rewriting the user's quoted words."

**Status of disclosure:** `logs/experiments/reports/north_star_integration_20260906/implementation-validation.md:71-73` discloses it as a residual POC limitation. But the spec row still specifies omission, and neither `north_star_moment.md` nor the PRD records the deviation — so the shipped behaviour contradicts its own contract. It never fired in the 36-week run (`budget.json` shows only `quote_not_exact_substring` invalidations, all recovered on retry), so it is latent, and most likely on the live onboarding path with free-form user text.

**Smallest fix:** demote the label hit from a batch-level `ReviewValidationError` to an entry-level exclusion that `select_moment`/`_pick` skip; or narrow `_INTERNAL_LABEL_PATTERN` to snake_case/underscored forms only. Add a test with a quotation containing standalone "security".

## Questions and risks (not confirmed defects)

- **Live deployment prerequisite.** `_SeededLiveLedger._seed` (`src/north_star/live_runtime.py:60-113`) hard-requires `logs/experiments/reports/north_star_integration_20260906/{budget.json,report.json}` (2.3 MB) at runtime and fails closed otherwise. Every live NSM review would return `budget_unavailable`. I could not verify the Experience Railway image — `railway.json` builds `Dockerfile.review_app`, which is the Shiny drift-review app, not `src.demo.api`. Worth confirming and documenting alongside the existing `--env-file .env` note in `frontend/onboarding/README.md`.
- **Envelope durability.** The live ledger writes under git-ignored `logs/exports/demo_tool_runs/north_star/`. On an ephemeral container it resets each deploy, so the approved US$20 cumulative envelope is enforced per container, not globally. The README warns against deleting the ledger but not about ephemeral hosts.
- **Retry offered where it cannot succeed.** `useNorthStarReview.ts:122-125` surfaces Retry for `provider_unavailable` (missing key) and `north_star_not_ready`. The `north_star_not_ready` message "Complete this week's review first." is also inaccurate for `build_north_star_request` validation failures such as an unknown Core Value. (The frozen 2-attempt provider cap is correctly enforced — the ledger raises `Retry limit reached`, so no budget breach.)
- **Retained phase0/phase0b scripts do not carry prior spend.** `scripts/experiments/north_star_phase0b*.py` default to `config/evals/north_star_moment_v1.json`, which has no `prior_spend_usd`, while the luna and integration policies correctly chain `0.34732602 → 0.62978415 → 1.44526`. A paid rerun would authorize a fresh US$20 on top. Low likelihood (needs explicit `--run`), but the chain is inconsistent.
- **Pre-existing, not this branch.** `WeeklyExperience.tsx` still renders "Active Drift" / "No active Drift now." badges and headings. The NSM spec's terminology rule (present at base, `493bc086:docs/future_work/north_star_moment.md:85`) says application-written Experience text must not expose internal Drift states. The NSM card copy itself is clean.
